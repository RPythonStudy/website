2 Window 환경에서 R 설치

2.1 설치파일

CRAN (https://cran.r-project.org/index.html)에서 자신의 운영체제에 맞는 최신 버전을 다운로드 받아 설치합니다. 2025년 03월 01일 기준으로 - 64 bit 원도우용 설치파일은 R-4.4.3-win.exe 이 최신입니다.

2.2 설치경로

R 버전이 x.y.z이면 Window 운영체제의 경우 기본 설치폴더는 C:\Program Files\R\R-x.y.z로 되지만 연구회에서는 아래와 같이 추천합니다.

R Install Option Window
C:\R\R-4.4.3
C:\Program Files\와 C:\ 경로의 장단점

  • 대부분의 Windows 애플리케이션은 program Files 폴더에 설치되므로 시스템 소프트웨어와 애플리케이션을 관리하는 표준 위치이기 때문에 시스템의 정리가 용이합니다. 또한 Program Files 폴더는 특별한 시스템 권한을 요구하므로 일반 사용자가 이 폴더 내의 파일을 쉽게 변경할 수 없으므로, 악의적인 소프트웨어에 의한 변경으로부터 보호할 수 있습니다. 그러나 R 패키지를 설치하거나 업데이트할 때마다 관리자 권한이 필요하여 사용자가 R을 자유롭게 사용하고자 할 때 불편을 초래할 수 있고 `Program Files`는 경로 내에 공백을 포함하고 있어 일부 오래된 스크립트나 도구에서는 경로 내의 공백을 제대로 처리하지 못할 수 있어 문제가 발생할 수 있습니다.

  • C:\ 하부에 직접 설치 (예: C:\R): 패키지 설치나 업데이트 시 관리자 권한을 요구하지 않고, 경로에 공백이 없기 때문에, 모든 스크립트나 프로그램에서 호환성 문제 없이 이 경로를 사용할 수 있습니다. 그러나 사용자 권한으로 설치된 프로그램은 보안이 상대적으로 약할 수 있으며, 악의적인 소프트웨어에 의해 변경되기 쉽고, 표준 설치 위치를 사용하지 않는 경우, 시스템의 소프트웨어와 애플리케이션이 분산되어 관리가 어려워질 수 있습니다.

  • 결론적으로, 설치 위치를 선택할 때는 보안, 사용 편의성, 시스템 관리의 용이성 등을 고려해야 하는데, 개인 사용자나 개발 환경에서는 C:\R과 같은 사용자 지정 경로가 더 편리할 수 있으며, 기업 환경이나 보안이 중요한 상황에서는 C:\Program Files 폴더 하에 설치하는 것이 더 적합할 수 있습니다.

2.3 환경변수설정

설치완료 후에는 시스템환경변수에 R 실행파일경로를 지정해 두어야 합니다.

  • 사용자나 RStdio와 같은 프로그램에서 R을 호출할 때나 package등을 설치할 때 시스템에서 R 실행파일의 설치경로를 알아야 원할히 진행됩니다.

  • Win+R로 실행창을 열고 sysdm.cpl 을 입력하는 방식이 빠르며, 시스템속성 고급탭에서 환경변수를 선택한 후 시스템변수 목록에서 path를 선택한 후 새로만들기 또는 편집으로 R 실행파일의 경로를 지정해 주시면 됩니다.

3 WSL2/Ubuntu 환경에서 R 설치

3.1 필요성 및 장점

WindowsWindows 환경 대비 우수한 성능 WSL2를 통해 Ubuntu 환경에서 R을 실행하면, Windows 네이티브 환경에서 발생하는 I/O 병목현상이나 호환성 문제를 줄일 수 있습니다. 동일한 하드웨어에서도 Ubuntu 기반 R 실행은 전반적인 성능에서 유리할 가능성이 높습니다.

리눅스 기반 패키지 최적화 많은 R 패키지와 라이브러리들이 리눅스 환경에서 개발 및 최적화되고 있습니다. 이로 인해 최신 패키지 버전 및 의존성 관리가 원활해져 보다 안정적인 실행 환경을 제공합니다.

개발 환경의 유연성 및 자동화 Ubuntu는 강력한 쉘, 스크립트 기능 및 apt와 같은 패키지 관리 도구를 제공하여 개발자가 쉽게 환경을 구성하고 자동화할 수 있습니다. 이로 인해 데이터 분석, 모델링, 자동화 작업의 생산성이 크게 향상됩니다.

파일 시스템 및 데이터 처리 효율성 리눅스 파일 시스템은 대용량 데이터 처리와 복잡한 디렉터리 구조 관리에 최적화되어 있어 데이터 입출력(I/O) 성능과 시스템 관리 효율이 뛰어납니다.

보안 및 업데이트 관리 Ubuntu와 같은 리눅스 배포판은 정기적인 보안 패치와 업데이트를 제공하여 안정적이고 안전한 운영 환경을 유지할 수 있으며, 전반적인 시스템 보안 수준을 높입니다.

활발한 커뮤니티 및 문서 지원 전 세계의 리눅스 커뮤니티와 다양한 포럼, 문서 자료 덕분에 문제 발생 시 신속하게 해결책을 찾을 수 있어 개발자들이 시간을 절약할 수 있습니다.

다중 버전 관리의 용이성 rig와 같은 도구를 활용하면 여러 버전의 R을 손쉽게 설치하고 관리할 수 있습니다. 이는 기존 프로젝트의 호환성을 유지하면서 최신 버전의 기능을 테스트하거나 사용할 수 있는 큰 장점입니다.

리눅스 커널의 안정성과 자원 관리 Ubuntu는 리눅스 커널을 기반으로 하여 자원 관리 및 시스템 안정성이 우수합니다. 연산 집약적인 작업이나 대용량 데이터 처리 시 효율적으로 시스템 자원을 활용할 수 있습니다.

컨테이너 및 클라우드 환경과의 통합 용이성 Ubuntu 환경은 Docker와 같은 컨테이너 기술 및 클라우드 기반 인프라와의 통합이 용이하여, 데이터 분석 및 배포 작업에서 유연성을 극대화할 수 있습니다.

경량화 및 최적화된 시스템 자원 사용 WSL2/Ubuntu 환경은 불필요한 오버헤드를 줄이고 필요한 자원만 효율적으로 사용함으로써, 더욱 빠르고 안정적인 R 실행 환경을 제공합니다.

이와 같이, WSL2/Ubuntu 환경은 단순히 성능뿐 아니라 패키지 최적화, 자동화, 보안, 다중 버전 관리, 그리고 클라우드 및 컨테이너와의 통합 등 다양한 측면에서 R 개발 및 데이터 분석 작업에 최적화된 조건을 제공합니다.

3.3 R Install Manager(rig) 설치

이전버전의 R로 만들어진 프로젝트도 있으므로 최신버전을 설치하더라도 이전 버전도 유지할 필요가 있습니다. 리눅스( 및 macOS)에서 이를 위한 패키지 rig를 설치하도록 합니다. 이글은 rig github 사이트(https://github.com/r-lib/rig?tab=readme-ov-file#id-ubuntu-and-debian-deb-package)를 참고하였습니다.

3.3.1 GPG키 추가

Ubuntu Bash
`which sudo` curl -L https://rig.r-pkg.org/deb/rig.gpg -o /etc/apt/trusted.gpg.d/rig.gpg
  • 위 명령에서 which sudo는 sudo 명령의 전체 경로를 출력하여 실행에 사용하는 것입니다. 예를 들어, 시스템에 따라 /usr/bin/sudo처럼 확장되어 실행됩니다:
  • 결과적으로 curl 명령을 관리자 권한으로 실행하여, rig 패키지를 위한 GPG 키를 APT의 신뢰된 키 디렉터리에 설치하게 됩니다.

3.3.2 rig repository 추가

Ubuntu Bash
`which sudo` sh -c 'echo "deb http://rig.r-pkg.org/deb rig main" > /etc/apt/sources.list.d/rig.list'
  • 저장소를 /etc/apt/sources.list.d/rig.list 파일에 기록합니다.

3.3.3 rig 설치

Ubuntu Bash
`which sudo` apt update
`which sudo` apt install r-rig
  • 우분투에서는 패키지이름이 r-rig로 되어 있으므로 주의 요합니다.

3.3.4 rig 설치 검증

Ubuntu Bash
rig --version
  • 버전이 표시되면 성공입니다.

  • 아래의 명령으로 설치된 모든 R 버전을 조회할 수 있습니다.

rig list
bash
ben@kimbi-laptop:~$ rig list
* name   version  aliases
------------------------------------------
  4.4.2
* 4.4.3
  • 두 개의 버전이 설치되어 있으며, *가 붙은 4.4.3이 현재 사용중인 버전임을 알 수 있습니다.

  • 아래의 명령으로 원하는 R 버전으로 설정할 수 있습니다.

3.7 rig에 의한 버전별 설치 경로

  • rig를 통해 설치된 R 버전은 기본적으로 아래와 같은 경로에 설치됩니다.
  • 버전별 디렉토리: /opt/R/versions 하위에 각 R 버전별 디렉토리가 생성됩니다.
  • 심볼릭 링크: /opt/R/current는 현재 활성화된 R 버전(예시에서는 4.4.3)에 대한 심볼릭 링크로 관리됩니다.

※ 실제 설치 경로는 시스템 설정이나 rig 구성에 따라 달라질 수 있습니다.

5 R 매뉴얼

R을 심도있게 공부할려면 R 개발자들이 만든 매뉴얼 중 The R language definition과 R Internals이 적합할 것 같습니다 (https://cran.r-project.org/index.html). 하지만 처음부터 어려운 매뉴얼을 공부하는 것보다 자신의 자료를 분석하는데 필요한 명령과 함수들을 Help 기능 등으로 이해하는 방법으로 진행하는 것도 필요할 것 같습니다.

6 renv 독립적 패키지관리

원래 R에서 패키지는 해당버전 R의 설치폴더 하부의 library 폴더에 설치됩니다. renv는 R 프로젝트에서 패키지 의존성을 관리하기 위해 설계된 도구로써, renv를 설치하고 활성화하면 해당 프로젝트 폴더 하부에 renv 폴더가 만들어지고, 그 하부에 패키지를 설치하게 됩니다. 또한 설치된 패키지들의 정보를 renv.lock 파일에 관리하게 됩니다. 이러한 방법으로 R에서는 프로젝트별로 패키지를 관리할 수 있으므로 필자를 이를 추천합니다.

RStudio에서 새로운 프로젝트를 생성할 때 renv 사용여부를 check하면 자동으로 설정됩니다.

사용법에 대해서는 https://rstudio.github.io/renv/articles/renv.html 참고하시길 바랍니다.
