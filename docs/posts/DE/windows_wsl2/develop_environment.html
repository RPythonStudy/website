  • 또한 WSL2도 Windows의 하부시스템이자 계정에 따라 보안권한이 다릅니다. 이 문서에서는 아직 검증은 불충분하지만 Windows 표준사용자 계정에서 WSL2 개발환경을 구축하는 지침을 우선 다룹니다. (관리자권한 계정에서 WSL2 개발환경구축도 가능하지만, 보안상 취약해질 수 다 합니다.)

1 계정과 권한 이해하기

환경 구축의 첫 단계는 어떤 계정을 사용할지를 정하는 것입니다.

1.1 Windows

1.1.1 Built-in Administrator 계정

Windows 시스템에서 최상위 권한을 가지며, 보안상 기본적으로 비활성화해 두는 것이 원칙입니다. 이 계정은 긴급 복구 상황에서만 사용하시는 것이 바람직하며, 일반적인 운영이나 개발환경 구축에서는 사용하지 않으시는 것이 원칙입니다.

1.1.2 로컬 Administrators 그룹에 속한 사용자 계정(이하 관리자권한 계정)

소프트웨어 설치, 장치 드라이버 관리, 보안 정책 설정 등 시스템 관리 작업을 수행할 수 있도록 설계되어 있습니다. 개발환경 구축에서는 Built-in Administrator 계정보다는 안전하게 필요한 권한을 제공하므로, 관리 작업이나 초기 설정 계정으로 활용하는 것이 바람직합니다.

1.1.3 관리자권한이 없는 표준사용자 계정(이하 표준사용자 계정)

시스템 설정 변경이나 시스템에 소프트웨어 설치는 할 수 없지만, 자신의 계정 하부의 폴더에 소프트웨어 설치는 가능하며, 또한 문서 작성, 코딩, 인터넷 사용 등 일상적인 작업에는 이 계정을 사용하는 것이 권장됩니다.

저자의 경우 계정과 권한의 구조를 이해하지 못한 채 관리자권한 계정만으로 Windows를 사용해 왔었는데, 이는 사용은 편리했지만, 보안상 취약해져 프로그램 삭제가 완전하지 않거나 악성코드가 침투하는 문제가 생길 수 있음을 다소 이해하게 되었습니다.
그래서 이 지침에서는 Windows에서 개발환경을 구축하고자 하신다면, Docker와 같이 시스템서비스가 필요한 서비스들은 관리자권한 계정에서 관리자권한으로 설치한 후 표준사용자 계정에서 이를 사용하도록 제안합니다. 일반적인 개발환경구축에 필요한 앱들은 표준사용자계정에서 표준사용자 폴더에 설치하도록 제안합니다.

1.2 WSL2

1.2.1 root 계정

Linux 환경의 최상위 권한 계정입니다. 보안상 직접 사용하지 않는 것이 원칙입니다.

1.2.2 sudo 권한 계정

WSL2 설치 시 기본으로 생성되는 계정입니다. 이 계정은 sudo 명령을 통해 root 권한을 일시적으로 사용할 수 있습니다. 개발환경 구축 시 가장 적합합니다.

1.2.3 일반 사용자 계정

sudo 권한이 없는 계정입니다. 소프트웨어 설치는 제한되지만, 프로젝트 실행·테스트에는 적합합니다.

1.3 macOS

1.3.1 root 계정

기본적으로 비활성화되어 있으며, 보안상 직접 사용하지 않습니다.

1.3.2 sudo 권한 계정

macOS 최초 설치 시 생성되는 계정입니다. 기본적으로 sudo를 통해 root 권한을 일시적으로 사용할 수 있으며, 개발환경 구축에는 이 계정을 사용합니다.

1.3.3 일반 사용자 계정

sudo 권한이 없는 계정으로, 시스템 변경은 불가하지만 프로젝트 실행이나 코드 작성은 가능합니다.

2 WSL2 개발환경구축

2.1 현재 계정 권한확인

현재 로그인된 Windows의 계정이 어떠한 권한인지 확인부터 진행해봅니다. * Windows 설정/계정/사용자 정보
에서 현재 로그인한 계정의 권한을 확인할 수 있습니다. 관리자라고 되어 있으면 관리자권한 사용자 계정입니다.

2.2 표준사용자 계정 생성

(관리자권한 계정으로 개발환경구축을 원하시는 사용자는 해당사항이 없습니다.) * Windows 설정/계정/다른 사용자/다른 사용자 추가 기능
으로 추가할 수 있습니다. * Window 10의 경우 - 로컬 사용자 및 그룹이라는 창이 뜨면 - 좌축 컬럼의 사용자를 선택하고, 가장 우측 컬럼의 기타작업으로 들어가서, 새 사용자를 선택하여 진행합니다. - 사용자 이름을 지정하시고, 암호를 지정하시면 됩니다. (다음 로그온 시 사용자가 반드시 암호를 변경해야 함은 선택을 해제하시는 것이 편리합니다.) * Windows 11의 경우 - 이 사람이 어떻게 로그인을 합니까?에서 이사람의 로그인 정보를 가지고 있지 않습니다를 선택합니다. 이는 Microsoft 계정 없이 로컬 계정을 생성하기 위함입니다. - 개인정보제공을 동의합니다. - 계정만들기 단계에서는 Microsoft 계정없이 사용자 추가로 진행합니다. - 이 PC의 사용자만들기 단계에서는 사용자이름과 암호를 설정하시면 완료됩니다. - 계정유형변경 메뉴에서 확인해보면 관리자가 아닌 표준 사용자라고 나옵니다. * 이제부터는 윈도우버튼으로 로그인한 계정이 보이게 하여 클릭하면 로그아웃 옆의 점3개를 클릭하면 생성된 표준 사용자명이 나오며 이를 클릭해서 전환할 수도 있습니다. * 처음 로그인하는 과정에서는 몇가지 설정을 하게 되며 다소 시간이 소요됩니다.

2.3 Windows Terminal 설치

반드시 필요한 것은 아니지만 일반적인 터미널창에 붙여넣기가 질 호환되지 않는 문제가 있고, WSL2의 bash 터미널을 띄우기가 편리하기 때문에 일반적으로 설치가 권장됩니다. - Microsoft Store에서 Windows Terminal을 검색해서 설치
하시면 관리자계정에 설치가 됩니다. 이 앱은 관리자 계정에 설치하고 표준사용자 계정에서도 설치하면 이 때는 중복설치가 아니라 링크처럼 실행하게 됩니다. 그런데 표준사용자 계정에서만 설치하는 방법은 지원되지 않으므로 관리자권한 계정에서 먼저 설치합니다.
이하 아래의 Powershell을 사용하실 때 붙여넣기가 호환이 잘 될 것입니다.

2.4 WSL2 설치 설정

  • Window10 2014 (Build 19041) 이상
    에서는 Windows 하부 시스템으로써의 Linux를 안정적으로 사용할 수 있습니다.
  • systeminfo
    자신의 윈도우 운영체저 성능은 Powershell에서 systeminfo라는 명령으로 간단히 확인할 수 있습니다.
  • CPU의 가상화 지원여부
    Ctrl+Shift+Esc 키를 사용하여 작업관리자로 진입하고 성능/CPU에서 가상화: 사용/사용안함 무엇인지 확인
  • BIOS Virtualization Technology
    Windows 운영체제는 가능한데 CPU에 가상화: 사용안함으로 되어 있다면 BIOS에 들어가서 Virtualization Technology(Intel VT-x / AMD SVM) 항목을 직접 찾아 Enabled로 바꿔야 합니다.
    하드웨어적 점검 완료 후 소프트웨어적 설정 점검을 진행합니다.
  • Powershell 관리자권한: WSL과 Virtual 옵션상태를 알아봅니다.
Get-WindowsOptionalFeature -Online -FeatureName Microsoft-Windows-Subsystem-Linux
Get-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform
  • 만약에 disabled 상태 등이라면 아래의 명령으로 필요한 파일들을 추가로 설치하여 enabled 상태로 변경하시면 됩니다.
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
  • 설치과정 등의 문제로 삭제 후 다시 설치하고 싶다면 아래의 제거를 진행 후 위의 설치를 다시 실행합니다.
dism.exe /online /disable-feature /featurename:VirtualMachinePlatform /norestart
dism.exe /online /disable-feature /featurename:Microsoft-Windows-Subsystem-Linux /norestart
  • 설치든 제거든 부팅이 필요합니다.
  • WSL2 버전 지정이 필요합니다.
wsl --set-default-version 2

2.7 Ubuntu 패키지설치 이해하기

  • apt 개념
    • 리눅스에서는 윈도우처럼 프로그램 설치 파일을 직접 내려받아 실행하기보다는, 패키지 관리 시스템을 통해 설치와 업데이트를 합니다.
    • 패키지 저장소(repository): 인터넷에 있는 프로그램 모음집.
    • 패키지 메타데이터: 어떤 버전, 의존성(함께 필요한 다른 패키지), 설치 방법 등이 적혀 있는 정보.
    • 로컬 저장소 목록: 내 PC가 어떤 저장소를 참조할지 기록한 파일.
    • apt는 이 목록을 참고해 프로그램을 설치·삭제·업데이트합니다.
    • 이때 시스템 전체에 영향을 주는 작업이므로 관리자 권한이 필요합니다. 그래서 명령 앞에 sudo(super user do)를 붙입니다.
  • update와 upgrade의 차이
    • apt update
      저장소에서 최신 패키지 메타데이터를 내 PC로 가져옵니다. 쉽게 말해 “업데이트가 있는지 목록을 새로고침하는 것”입니다. 실제 프로그램이 설치되거나 바뀌지는 않습니다.
    • apt upgrade
      apt update로 가져온 목록과 현재 내 PC의 상태를 비교합니다. 새 버전이 있으면 인터넷에서 내려받아 설치합니다. 즉, “목록을 보고 실제로 프로그램들을 최신 버전으로 교체하는 것”입니다.

3.1 Scoop 설치

Windows용 command-line 패키지 설치 매니저입니다. * 이를 사용하지 않고 표준사용자 계정으로 설치를 진행해도 버전관리에 불편함에 있을 뿐이므로 원치 않으시면 패스하셔도 됩니다. * 또한 일부 패키지들은 native와 달리 원하는 버전이 아직 update되지 않아서 그냥 표준사용자 계정으로 설치하는 경우도 있습니다. * Docker Desktop처럼 부팅이후에 시스템서비스로 항상 구동되어야 하는 경우 관리자권한 사용자게정에서 시스템에 설치가 필요합니다. 따라서 이 경우도 scoop로 설치하지 않습니다. * 이미 많은 앱들이 설치된 표준사용자계정이라면 모두 scoop로 재설치하는 것보다 scoop 없이 진행할 수 있습니다. - 설치는 아래를 따라서 진행합니다. - Win+X 핫키를 이용해서 Windows PowerShell 터미널을 관리자권한이 아닌 상태로 엽니다. (표준사용자 계정에서는 어차피 관리자권한으로 열리지는 않을 것 같습니다.) - 아래의 명령으로 Powershell이 다운로드한 파일도 실행할수 있도록 실행권한을 재설정합니다.

3.9 표준사용자 Rtools 설치 (옵션)

  • Rtools는 R이 단순 스크립트 언어로만 쓰이지 않고, C/C++/Fortran 확장 패키지를 Windows에서 문제없이 빌드할 수 있게 해주는 컴파일러·빌드 환경입니다.
  • 차후에 필요시 설치를 해도 무방합니다.
  • CRAN으로부터 설치파일을 다운도르하여 표준사용자 폴더 C:<사용자명>직접 설치를 진행하였습니다.
  • 설치 후 경로를 설정해야 하는데 앞서 이 프로젝트에서는 make란 자동화도구를 사용했는데, 이것이 이름이 같기 때문에 단순히 경로를 설정하면 앞서의 make가 호출되는 문제가 발생합니다. 이 문제를 극복하기 위해 표준사용자 환경변수에 rtools 경로를 주입하는 아래의 방법으로 진행하였습니다.
  • C:<사용자명>.Renviron 파일을 생성하고, 아래의 경로를 설정해 줍니다.
PATH="C:/Users/<사용자명>/rtools44/usr/bin;${PATH}"
  • .Renviron 파일은 이 위치에 있으면 사용자전역으로 환경설정을 하여 R session이 시작될 때, 인식하게 됩니다.

3.11 표준사용자 quarto 설치

  • Quarto 문서를 렌더링 등에 필요합니다.
  • 1.6.42 버전에서는 RPythonStudy/website 렌더링시에 오류가 없었으나 이후의 버전에서 오류가 발생하였습니다.
  • 이 프로잭트에서는 Quarto 버전을 아래와 같이 표준사용자 환경에 설치하였습니다.
scoop install quarto@1.6.42
  • 설치 검증은 버전으로 하시면 됩니다.
quarto --version
